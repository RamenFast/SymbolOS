# Twelve rings: a vocabulary for the work

The rings give us names for different questions in a task. They are a conceptual map, not operating-system privilege levels or measured layers inside a model.

The earlier eight-ring version is still present in historical prompts and the terminal prototype. The twelve-ring proposal added **Will, Sensation, Reflection and Integration**, shifting the numbering of several older concepts. A reference to “R4” is therefore ambiguous unless its version is clear.

## The questions

- **R0 / Kernel:** What purpose and governing constraints should remain in view?
- **R1 / Will:** What are we choosing to work on, and whose request authorizes it?
- **R2 / Sensation:** What have we actually observed, from which source and when?
- **R3 / Task:** What is the specific outcome in front of us?
- **R4 / Retrieval:** Which prior decisions or files are relevant now?
- **R5 / Prediction:** What might happen, and which assumptions could be wrong?
- **R6 / Architecture:** How should the pieces and their interfaces fit together?
- **R7 / Guardrails:** What are the ownership, privacy and change boundaries?
- **R8 / Verification:** Which observed check would establish the result?
- **R9 / Persistence:** What should be saved, where, and with what provenance?
- **R10 / Reflection:** Where did the result differ from the intention?
- **R11 / Integration:** What should the next reader or session understand differently?

These questions support a conversation. They do not require twelve response sections or twelve running agents.

## Reading older references

The eight-ring vocabulary used Task at R1, Retrieval at R2, Prediction at R3, Architecture at R4, Guardrails at R5, Verification at R6 and Persistence at R7. Kernel remained R0.

The twelve-ring vocabulary moves those seven roles to R3 through R9. Do not silently reinterpret an old score, color, test or API field using the newer number.

The shared JSON's notes and older prompts mix the two versions. The desktop TUI renders eight rings. A historical implementation plan is not proof that every consumer was migrated.

## A concrete example

For this repository's curation, the user outcome is useful, readable material rather than an unexamined archive copy. Reading each file supplies observations. A per-file decision records relevance. Rendered reading paths test the presentation. The remaining-file count stays open until the whole corpus is reviewed.

Rhy asks: *“Does the number tell you what to do, or does the question?”*
